# Сохранение заметок

## Общая модель

Каждый блок имеет стабильный UUID v7. Редактирование текста, изменение типа или
перемещение не меняет идентификатор блока.

Фронтенд хранит два состояния:

- `previous` — последнее состояние, подтверждённое сервером;
- `current` — текущее состояние редактора.

Перед сохранением фронтенд сравнивает эти состояния по `blockId` и формирует
только необходимые операции. Вся заметка при обычном редактировании не
отправляется.

## Время сохранения

После первого изменения запускаются два таймера:

- `idle timer` — сохранение через 1 секунду после последнего изменения;
- `max timer` — обязательное сохранение через 5 секунд после начала непрерывной
  серии изменений.

Каждое следующее изменение сбрасывает только `idle timer`. `max timer` не
сбрасывается. После сохранения начинается новое временное окно.

Сохранение также запускается перед переключением заметки, при скрытии вкладки и
при закрытии страницы.

## Вычисление операций

### `create`

Блок присутствует в `current`, но отсутствует в `previous`.

```json
{
  "type": "create",
  "block": {
    "id": "019...",
    "type": "paragraph",
    "props": {},
    "content": []
  },
  "parentId": null,
  "position": {
    "before": null,
    "after": "019..."
  }
}
```

### `update`

`blockId` сохранился, но изменились `type`, `props` или `content`.

```json
{
  "type": "update",
  "blockId": "019...",
  "block": {
    "type": "paragraph",
    "props": {},
    "content": [
      {
        "type": "text",
        "text": "Новый текст",
        "styles": {}
      }
    ]
  }
}
```

### `delete`

Блок присутствовал в `previous`, но отсутствует в `current`.

```json
{
  "type": "delete",
  "blockId": "019..."
}
```

### `move`

У блока изменился `parentId` или порядок среди соседних блоков. UUID блока и
его дочернее дерево сохраняются.

```json
{
  "type": "move",
  "blockId": "019...",
  "parentId": "019...",
  "position": {
    "before": "019...",
    "after": "019..."
  }
}
```

Чтобы перестановка одного блока не создавала ложные `move` для остальных,
фронтенд находит максимальную подпоследовательность блоков, порядок которой не
изменился. Операция `move` создаётся только для блоков вне этой
подпоследовательности.

Если одновременно изменились содержимое и положение блока, создаются две
операции: `update` и `move`.

## Относительная позиция

Порядок задаётся UUID соседей:

```ts
type RelativePosition = {
  before: string | null;
  after: string | null;
};
```

- первый блок: `{ before: null, after: "next-id" }`;
- блок между соседями: `{ before: "previous-id", after: "next-id" }`;
- последний блок: `{ before: "previous-id", after: null }`;
- единственный блок: `{ before: null, after: null }`.

`before` является основным якорем вставки. `after` позволяет проверить
ожидаемого следующего соседа и может указывать на блок, создаваемый позднее в
той же транзакции.

## API транзакций

Изменения отправляются запросом:

```http
POST /api/notes/:noteId/saveTransactions
Content-Type: application/json
```

```json
{
  "transactions": [
    {
      "id": "019...",
      "operations": [
        {
          "type": "update",
          "blockId": "019...",
          "block": {
            "type": "paragraph",
            "props": {},
            "content": []
          }
        }
      ]
    }
  ]
}
```

За один запрос принимается от 1 до 100 транзакций. Каждая транзакция должна
содержать хотя бы одну операцию.

На сервере:

1. Открывается транзакция PostgreSQL.
2. Заметка блокируется через `SELECT ... FOR UPDATE`.
3. Операции применяются последовательно по их типу.
4. Проверяется структура и глубина дерева.
5. Обновлённые блоки сохраняются.
6. Выполняется `COMMIT`.

При любой ошибке выполняется `ROLLBACK`, поэтому частичное применение пакета
невозможно.

Ответ содержит обновлённую заметку и идентификаторы применённых транзакций:

```json
{
  "id": "note-id",
  "title": "Название",
  "blocks": [],
  "appliedTransactionIds": ["019..."],
  "createdAt": "2026-09-23T10:00:00.000Z",
  "updatedAt": "2026-09-23T10:05:00.000Z"
}
```

Заголовок заметки сохраняется отдельно:

```http
PATCH /api/notes/:noteId
```

```json
{
  "title": "Новое название"
}
```

## Плоские блоки и `children`

Бэкенд возвращает плоский массив блоков. Каждый элемент содержит `parentId` и
относительную позицию:

```json
{
  "id": "child-id",
  "parentId": "parent-id",
  "position": {
    "before": null,
    "after": null
  },
  "type": "paragraph",
  "props": {},
  "content": []
}
```

Фронтенд создаёт индекс `Map<blockId, block>` и формирует `children` по
`parentId`. Блоки с `parentId: null` становятся корневыми.

Максимальная глубина дерева — 5 уровней, где корневой блок считается первым
уровнем. Бэкенд и фронтенд отклоняют:

- шестой уровень вложенности;
- отсутствующего родителя;
- циклическую ссылку через `parentId`;
- блок, не связанный с корнем заметки.

## Создание новой заметки

До появления `noteId` транзакции отправлять нельзя. Поэтому новая заметка
создаётся целиком:

```http
POST /api/notes
```

После получения `noteId` последующие изменения сохраняются только через
`saveTransactions`.

## Очередь запросов

Одновременно выполняется только один запрос сохранения. Если пользователь
продолжил редактирование во время запроса, новые изменения остаются в текущем
локальном состоянии и отправляются следующей транзакцией после подтверждения
предыдущей.

После успешного ответа отправленный снимок становится новым `previous`. При
ошибке снимок не обновляется, поэтому изменения остаются несохранёнными и могут
быть отправлены повторно.

## Связь с подходом Notion

Архитектура использует те же базовые идеи, что и Notion: стабильные ID блоков,
операции над отдельными записями, оптимистичное локальное состояние, очередь и
атомарные транзакции.

Отличие: Notion формирует операции непосредственно из действий пользователя и
транзакций редактора. В текущей реализации операции вычисляются сравнением
последнего подтверждённого снимка с текущим состоянием Tiptap. Таймеры 1 и 5
секунд, относительная позиция и алгоритм вычисления `move` являются решениями
этого проекта, а не подтверждёнными деталями реализации Notion.
